# DESIGN.md

How the app is built and how it should look. Keep this file in sync when you change structure or visual rules.

## Architecture

One activity per screen, all in package `carl.coding` (`app/src/main/java/carl/coding`). There is no shared view model or repository layer. Each screen owns its small state, and pure logic lives in plain classes.

| Class | Role |
| --- | --- |
| `RandomizerApp` | `Application`; applies the saved light/dark mode at startup. |
| `BaseActivity` | Base of every screen: main-thread `handler` cleared on destroy, `vibrate(ms)`, `open(Class)`. |
| `StartMenu` | Launcher screen: one button per feature, plus the theme toggle. |
| `CoinActivity`, `DiceActivity`, `YatzyActivity`, `NumberActivity` | Single-screen features. |
| `CategoriesSetupActivity` → `CategoriesActivity` | Enter options, then pick (optionally withdrawing picks). |
| `TeamSetupActivity` → `TeamResultActivity` | Enter players and team count, then show shuffled teams. |
| `EditableList` | Rows of text inputs with Remove buttons, used by both setup screens (`item_editable_row.xml`). |
| `Dice` | Die face drawables and roll animation timing shared by Dice and Yatzy. |
| `RandomRange`, `Teams` | Pure, unit-tested logic: uniform `long` in a range; team-count parsing and even splitting. |
| `PreferencesHelper` | `SharedPreferences` wrapper (`randomizer_prefs`): dark mode, strings, booleans, string lists (JSON). |

### Patterns

- **Roll animations**: post a sequence of `handler.postDelayed` steps that show intermediate values in `text_feedback_muted`, then a final step that shows the result in `text_primary`, re-enables the button and vibrates. Disable the action button while rolling.
- **Persistence**: setup inputs are saved in `onPause` and when starting the result screen. Results are not persisted; they survive rotation only (`freezesText` or `onSaveInstanceState`).
- **Navigation**: forward with `open(...)` or `startActivity`; back is the system back. Slide animations are defined once in `Theme.Randomizer` (`Animation.Randomizer.Slide`).
- **Theme**: the app has its own light/dark toggle, stored in prefs and applied with `AppCompatDelegate.setDefaultNightMode`. It does not follow the system setting.

### Adding a feature

1. Add `XxxActivity extends BaseActivity` and `res/layout/activity_xxx.xml` following the screen layout below.
2. Register it in the manifest (`exported="false"`), add a menu button in `activity_start_menu.xml` plus a `goXxx` method in `StartMenu`, and add strings.
3. Put any non-trivial random logic in a plain class with a JUnit test.
4. Add the feature to the README table and `scripts/capture_readme_screenshots.sh`, then regenerate screenshots.

## Visual design

A calm, rounded "card on tinted background" look in a single blue accent, with full light and dark palettes.

### Color tokens

Defined in `res/values/colors.xml` (light) and `res/values-night/colors.xml` (dark). Always reference tokens, never literals.

| Token | Light | Dark | Use |
| --- | --- | --- | --- |
| `screen_background` | `#F4F7FF` | `#0F172A` | Window and screen roots |
| `surface_background` | `#FFFFFF` | `#162033` | Panels, inputs, theme toggle |
| `surface_stroke` | `#D8E3FF` | `#27334B` | 1dp panel/input borders |
| `text_primary` | `#14213D` | `#F8FAFC` | Titles, results, input text |
| `text_secondary` | `#60708A` | `#B7C3D8` | Subtitles, hints, status lines |
| `text_feedback_muted` | `#8A96A8` | `#6F7E99` | Intermediate values while rolling |
| `accent` | `#4D7EF7` | `#6E97FF` | Buttons, held dice, switches |
| `accent_pressed` / `accent_disabled` | `#3D68D7` / `#A8BEF6` | `#88AAFF` / `#42537A` | Button states |
| `button_text` | `#FFFFFF` | `#FFFFFF` | Text on accent buttons |
| `hold_highlight` | accent at 15% | accent at 20% | Fill behind a held Yatzy die |

### Components

- **Panel**: `@drawable/panel_background`, 28dp corners, 1dp `surface_stroke`, 20–24dp padding.
- **Button**: `style="@style/Widget.Randomizer.Button"`, 56dp tall, 22dp corners, 18sp, sentence case (never all caps). Inline row buttons such as Remove use the same style at 14sp.
- **Input**: `style="@style/Widget.Randomizer.Input"`, 18dp corners.
- **Title**: `style="@style/Widget.Randomizer.Title"` (26sp bold), followed by a 15sp `text_secondary` subtitle.
- **Result text**: bold, 32–48sp, `text_primary`, centered.

### Screen layout

`ConstraintLayout` on `screen_background` with 24dp side margins (20dp on setup screens). The content panel is centered vertically (bias about 0.6) and the primary action button is pinned 24dp above the bottom. Setup screens use a header panel, a scrolling list panel and a bottom row of two buttons.

### Launcher icon

A dark navy gradient (dark-theme surfaces) behind an accent-blue die showing five over an outlined surface-colored die. It is generated by `scripts/generate_icon.py` as an adaptive icon (with a monochrome layer), legacy PNG mipmaps, the start-menu `logo` and the README icon.
